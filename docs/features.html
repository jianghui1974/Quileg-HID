1. 它是什么

一个 macOS 桌面 App，同时承担三件事：

iPhone ─AirPlay─▶ UxPlay ─────┐
iPhone ─HDMI───▶ UVC 采集卡 ──┴─▶ 帧（手动选源）─▶ App（控制台 + hidagent :8890）
                                                    ├─▶ MCP 工具（给 AI 宿主）
被控设备 ◀─ BLE HID ◀─ 板子 ◀─ Wi-Fi TCP 7300 ─────┘
（iPhone / iPad / Android / Mac / Windows）
  • 眼睛：AirPlay 接收端（UxPlay）或 UVC 采集卡；两路同时跑，手动选源，也可并排监视；
  • 手：ESP32-S3 板子做 BLE 键鼠，Mac 通过 Wi-Fi TCP 发指令；键盘组合按「被控设备」白名单放行；
  • 接口：本机 :8890 同时服务 GUI、控制层和 MCP。

2. 三个入口

入口命令说明
GUIQuileg HID.app控制台 + 服务端（打包版由 launcher 起 hidagent）
MCP stdioHIDBridge --mcp宿主拉起；:8890 已在跑就复用，否则自己起
后台启动--background登录自启用，不显示窗口

GUI 是常驻服务：红叉只隐藏窗口，⌘Q 才退出（见 运行方式：常驻与退出）。

5. 出问题先看什么

iPhone 两个总开关：辅助触控 不开 → 没有鼠标指针（click/move 全像没反应）； 鼠标键 → 使用主键盘 开着 → 键盘变鼠标（i j k l m o u 7 8 9 . 不落屏、回车弹菜单）。 路径：设置 → 辅助功能 → 触控 → 辅助触控（→ 指针设备 → 鼠标键）。详见 排障与兼容性。

按顺序，不要凭感觉重装：

  1. app_status：App 版本/模式、板子是否连、投屏是否在、固件版本、端口；
  2. app_logs：最近 10 分钟的错误（level=ERROR 或 grep 关键字）；
  3. app_diagnostics：一份可直接贴给用户的报告（版本、USB 端口、设置、日志尾巴）；
  4. status（iPhone 工具）：device/screen/calibrated/ble；
  5. 再决定：重投屏、重配网、重启 App，还是刷固件。

常见判断：

现象先看结论
所有工具 connection refusedDock 图标 / :8890App 被 ⌘Q 退出或服务没起
device=falseapp_status 的 USB/板子板子没上电/没连 Wi-Fi/端口被占
screen=false手机控制中心没选投屏，或接收端没起
点击偏calibrated + 设备基线校准表不是这台设备的
固件升级失败app_status 的 app/firmware版本、stub、端口占用
配网后离线app_logs grep Wi-Fi5 GHz/密码错/天线没接
打字时个别字符不出现（如 i j k l m o u 7 8 9 .）/ 回车弹菜单检查 辅助功能 → 触控 → 辅助触控 → 指针设备 → 鼠标键 → 使用主键盘该开关开着时键盘被当成鼠标，不是固件；关掉即恢复，辅助触控要保持开
⌘Tab 没反应—iPhone 没有这个系统快捷键；用 ⌘H + ⌘Space 切 App

6. AI 的边界

可以做：读状态/日志/诊断、操作 iPhone、建议改设置、把用户带到正确的对话框。

要先问用户：改 Wi-Fi/服务器地址、重启板子、重装/升级固件、退出 App、取消校准。

不要做：无人值守刷固件、输入密码/验证码、替用户发消息或支付、修改账号安全设置。

诊断工具全部只读，且日志已脱敏（密码/token 不会出现在结果里）。
